# CONTEXT.md — Webview (`src`)

The **React 19 + TypeScript** webview — the presentation layer. It is a
**projection/cache** of the Rust core's state, never a source of truth,
and it **does not speak gRPC**.

Read `../CONTEXT.md` for the project overview; transport detail is in
`../src-tauri/CONTEXT.md`. For per-ADR status see `cambrian-knowledge/adrs/`.

---

## Scaffold

Vite, React 19, Bun, Tailwind CSS, Radix UI primitives. ~894 vitest tests
(94 files, 2026-11-06); `tsc --noEmit` clean. `src/routeTree.gen.ts` is generated by
the TanStack router Vite plugin (`bun run build` / `bun run dev`) — never hand-edit it.

---

## Module Map

| Area | Responsibility |
|---|---|
| `ipc/` | Tauri client: `invoke(...)` intents and `listen(...)` projection events. The ONLY way the webview reaches the runtime. |
| `store/` | Zustand projection store hydrated from `kernel://state`. A cache, not the state of record. Re-hydrates via `op_get_state` on mount/reload. |
| `screens/` | One screen per PRD surface. The plan view is the centre of gravity when a plan runs. |
| `design-system/` | Tokens, components, utilities. Light, dark (default follows the OS) and Nocturne themes; dense, keyboard-friendly, accessible. Text roles are `type-*` utilities in `styles/type.css` (page title, description, section title, label, status, figure) — use them instead of hand-sized text, and keep labels sentence case. Screen building blocks: `PageHeader`, `SectionHeader`, `Stat`, `Callout`, `KeyValue`, `EmptyState`, `Card` (`tone`, `interactive`), `Badge` (`dot`). |
| `lib/queryClient.ts` | TanStack Query — imperative edges only (mutations + request/response reads not on the feed). Every automatic refetch disabled. Nothing on `kernel://state` may be cached here. |

---

## Data Flow

```
Rust core ──kernel://state──> store ──> React screens
React screens ──invoke('op_*')──> Rust core ──gRPC──> kernel
```

- **Reads are push, writes are intents.** No "click to refresh".
- Every `invoke` mutation requires a **`reason`** (kernel rejects empty).
- `command_id` and token are the Rust core's job.

---

## Themes

`data-theme` on `<html>` selects `light`, `dark` or `nocturne`; the operator's
preference (`system` | `light` | `dark` | `nocturne`) lives in `shellStore`,
is saved to `localStorage` (`cambrian-studio:theme`, `cambrian-studio:density`),
and is applied before React mounts by `public/theme-boot.js`. `system` follows
the OS. Fonts (Inter, Geist Mono) are bundled via `@fontsource-variable/*` — no
remote font fetch. Base styles are in `@layer base` so Tailwind utilities win.

## Shell Composition

Full-height sidebar (brand, search, then the Work / Knowledge / Automate / Admin
groups below — Inbox is a Work entry with its badge — and Settings, role and the
collapse toggle at the foot), a header in the main column (breadcrumb, version
alert, connection popover, identity, sign-out), the routed main pane, and an
**inspector slot**
(`InspectorSlot.tsx`) mounted only while a screen is inspecting something.
No screen renders its own permanent aside. No bottom status strip.

**Information architecture (redesign 2026-11-06,
`cambrian-knowledge/investigations/2026-11-06-operator-console-redesign.md`).** The rail
(`design-system/components/cambrian/nav-rail.tsx`, `NAV_GROUPS`) has four groups:

| Group | Entries (capability gate) |
|---|---|
| Work | Chat (home; `/` redirects here) · Inbox (badge) · Tasks |
| Knowledge | Memory (documents · notes) · Skills (`skills-read`/`skills-lifecycle`/`skill-grants`) · Knowledge (`substrate-query`) · Link review (`links`) |

Knowledge → Explore entity card: `LineageSection` (ADR-0148, 2026-11-12) asks `why` for STORED lineage only and shows the kernel's hint row verbatim; "Show related events (not causal)" opts in with `include_correlation` and renders `row:"related"` rows (with score) and flagged hub participants in a separate "Related — not causal" section, never mixed into the lineage list.
| Automate | Integrations · Pipelines (`watches-read`) · Plan builder · Ingress Studio (`ingress-studio`) · Telegram (`telegram-ingress`) |
| Admin | Runtime (agents · tools · MCP) · Access policy (`access-policy`) · Organisation (`org-directory`) · Audit (`audit`) · Logs (`kernel-logs`) · Plugins |

**One gating rule**: `entryAvailable(entry, capabilities, role)` (`requires` / `requiresAny`,
plus `forMembers` for what an ADR-0142 `member` may reach) for the rail,
`routeAllowedForRole` (`lib/roleGate.ts`) in `Shell` for deep links, `useCapability()` (`lib/useCommandGate.ts`) inside screens. `useCommandGate()`
is the one "why is this control disabled" rule (Viewer, reconnecting, down).

Deleted 2026-11-06 (rendered state nothing populates, or duplicated another screen):
Now, Plans in flight, Verifier Pool, Lifecycle, Cost & Energy, PlanWorkSurface/PlanGraph,
AgentOutputStream, the header spend/breaker readouts. `StateOfRecord` still carries the
never-populated `lifecycle` / `verifier_pool` / `cost_dashboard` fields
(T-20261106-state-of-record-still-carries-never-populated).

## Live state that is not on `kernel://state`

| Lane | Where it lands |
|---|---|
| `kernel://token` (TokenChunkOp, capability `step-output-stream`) | `lib/stepOutput.ts` — one subscription in `Shell`, batched ~100 ms, folded by lease + `chunk_seq` (dedupe, hole count, final), grouped per task/step by `runsForSession`; rendered by `screens/run/LiveOutput.tsx` in Chat and the task surface. Extra leases on one step render nested as *inferred* sub-runs (no parent lease on the wire). |
| Inbox sources without a feed event (skill proposals, timed-out skill-access requests) | `lib/useInbox.ts` reads them with `useKernelQuery`, re-read on mount, focus, skill-related audit records and after this console's own decisions (`refreshInbox`). `lib/inbox.ts buildInbox` merges them with feed HITL; the rail badge and the Inbox screen use the same aggregation. |
| Integration health | folded in the Rust core into `StateOfRecord.integration_health`; `lib/integrations.ts effectiveHealth` prefers it over the listed health when newer. |

## Screens added 2026-11-06

- `screens/settings/ConnectionSettings.tsx` — sign-in methods from DescribeAuth
  (`lib/loginMethods.ts`), the single-sign-on button, the identity panel.
- `screens/organisation/*` (`/organisation`, capability `org-directory`) — org tree, mapping
  rules with preview-before-save, who approves what, SCIM (token shown once), directory sync.
  Logic in `lib/hierarchy.ts`; plane in `ipc/hierarchy-client.ts` / `ipc/hierarchy-mock.ts`.
- `screens/inbox/UnroutedApprovals.tsx`, `EscalationChain.tsx` — approvals that ended
  needs_hierarchy / unroutable, and the requester's manager chain on supervisor-routed items
  (`lib/approvalRules.ts`).

- `screens/inbox/InboxConsole.tsx` — every pending decision: tool approvals (with the
  WatchToolApprovals `args_preview`), live skill-access requests (ResolveHITL), timed-out
  access requests (GrantSkill only — no deny RPC), skill proposals (DecideSkillProposal,
  diff + scan verdict, optional lock).
- `screens/skills/SkillsConsole.tsx` (`/skills?tab=`) — catalog, proposals, ledger + rollback,
  grants. Diff: `lib/lineDiff.ts` (LCS, no dependency).
- `screens/memory/NotesPane.tsx` (Memory › Notes, capability `memory-notes`) — etag-guarded
  editor, state machine in `lib/notesEditor.ts`.
- `screens/integrations/IntegrationsConsole.tsx` (`/integrations`) — the external-systems list
  (`SystemsList`) above the MCP catalog (install, write-only credentials); without
  `integrations` it shows the configured MCP servers read-only.
- `screens/integrations/SystemPage.tsx` (`/integrations/$systemId`, ADR-0141 D9) — one page per
  external system: **Accounts** (`AccountsSection`: org accounts — create, rotate/replace key,
  rename, bind/unbind to a server slot, revoke; *my account* — connect via the system browser,
  confirm a pending sign-in by its identity, reconnect, disconnect; operators: everyone's
  personal accounts + revoke), **Data in** (ingresses bound to the system's org accounts, status,
  pause/resume, link to Ingress Studio), **Agent actions** (the system's MCP servers via
  `InstalledCard`, tool policies; per-server Credentials hidden when account-backed). Data:
  `useSystems` (each read gated on capability/role) → `lib/accounts.ts buildSystems`. With
  capability `accounts-systems` the kernel's premium system catalog (`ListSystems`) decides
  membership and the console derives only what it does not claim (an older kernel: everything);
  operators get **Install for the organization** (`StartOrgAccountInstall`, OAuth bot install /
  admin consent opened in the system browser, also "Grant more permission" = incremental
  consent on an installed account), per-grant "needs more permission" verdicts, and the revoke
  dialog lists what stops (`ListAccountConsumers`); a person's account short of a server's
  scopes shows Reconnect and an Inbox entry. All
  account state/actions/flow/aggregation logic is pure in `lib/accounts.ts` (tested in
  `accounts.test.ts`); mock plane `ipc/accounts-mock.ts`.
- `screens/settings/ProviderClientsSettings.tsx` (Settings › OAuth providers; `accounts` +
  Operator) and `screens/ingress-studio/AccountPicker.tsx` (org-account binding per credential
  row). `screens/inbox/AccountItem.tsx` renders account Inbox items with the system page's card.
- `screens/run/RunApprovals.tsx` — the run's pending approvals inline in Chat
  (`approvalsForRun`: by session/plan, or inferred by running agent for hub approvals).

## Key Invariants

- The webview holds no kernel state the core didn't give it.
- Role/capability reflection: hide/disable mutating controls for Viewers; hide surfaces the kernel doesn't advertise.
- Plugin surfaces wrap in `PluginSurface.tsx` — skew banner + absent state by construction.
